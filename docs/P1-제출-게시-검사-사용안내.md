# P1 제출·게시 검사

P1은 현재 `agentctl`의 완료 제출과 `repoctl finish`의 게시 경로에서 검사를 강제합니다.

## 적용 대상

`.agent-work/gates.json`에 선정된 `multi / agent-framework / development`의 새 작업부터 등록합니다. 이슈는 각 작업의 정확한 범위를 사용합니다. 등록 전에 시작된 작업과 과거 제출 기록은 기존 방식으로 유지합니다.

작업 등록 당시의 범위·기준 커밋·설정과 정책을 고정합니다. 등록된 작업의 제어 파일을 삭제하거나 설정을 낮추어 완료하는 방식은 허용하지 않습니다. 로컬 등록 기록 자체를 수정할 수 있는 사용자까지 막는 보안 경계는 아닙니다.

## 작업 순서

1. 기존 방식으로 범위를 지정해 `agentctl init`하고 작업 소유 파일을 `repoctl track`으로 등록합니다.
2. 구현·사용자 산출물·작업 명세를 정리한 뒤 `python runtime/control_gate.py candidate --task <작업ID>`로 검사 대상을 확인합니다. 최종 `result.json`과 거기에 참조하는 시험·검토 근거도 평가 등록 전에 확정해야 합니다.
3. `python runtime/control_gate.py run-tests --task <작업ID> --suite <설정된-suite-ID>`로 각 필수 시험을 실행합니다. 명령·실행 결과·로그와 실행 전후 파일 내용을 기록합니다.
4. 작성자가 아닌 evaluator가 실제 파일과 시험 증거를 검토하고, 결과에 참조된 검토 보고서를 완성합니다. evaluator가 직접 평가 입력을 작성하고 `python runtime/control_gate.py assess --task <작업ID> --input <저장소-상대경로>`로 기록합니다. 평가의 `evidence`에는 최종 산출물과 보존할 검토 근거를 포함합니다. 평가 등록 뒤에는 결과나 근거 파일을 수정하거나 생성된 평가 기록을 결과에 추가하지 않습니다.
5. `python runtime/control_gate.py status --task <작업ID>`와 `agentctl validate`로 현재 상태를 확인한 뒤 `agentctl submit`, `repoctl finish`를 실행합니다.

평가 입력에는 `candidate_digest`, `reviewer`의 `subject`·`session`, `verdict`, 현재 작업의 검토 근거 파일 경로 배열인 `evidence`가 필요합니다. verdict는 `accepted`, `rework`, `inconclusive` 중 하나입니다. 평가자 이름은 선언된 구분값이며 인증된 신원은 아닙니다.

## 차단과 재검증

필수 시험이나 독립 검토 누락, 시험 실패, 검토 이후 파일·증거·정책 변경, 작업 범위 불일치는 완료 제출을 차단합니다. 수정 후에는 변경된 내용을 대상으로 필요한 시험과 검토를 다시 수행합니다. 기존 증거의 해시나 판정을 고쳐서 통과시키지 않습니다.

P1은 검토한 파일·정책·증거의 일치를 확인합니다. 거버넌스의 `proceed`만으로 P1 필수 검증을 충족하지 않습니다.

게시 검사는 제출한 대상과 실제 생성된 커밋, 변경 경로, 부모 커밋, 승인된 원격·브랜치를 대조합니다. 게시 검사나 푸시가 실패하면 생성된 커밋을 보존하고 원인을 해결한 뒤 같은 작업의 `finish`를 재시도합니다. 강제 푸시나 별도 완료 커밋 생성으로 우회하지 않습니다.

## 범위와 한계

현재 로컬 CLI를 따르는 작업에 대한 검사입니다. 에이전트 지침, 로컬 시험 실행 기록, 파일 해시는 서명된 신뢰 증명이나 규제 준수 인증이 아닙니다. 작성자와 평가자는 동일 운영체제 사용자 권한으로 파일에 접근할 수 있습니다. 직접 Git 사용·구버전 CLI·로컬 검사 코드나 등록 원장 전체 변경을 막으려면 호스트 격리와 보호된 게시 서비스 또는 원격 서버 검사가 추가로 필요합니다.

새 clone에서는 `python -m venv --copies .venv-controls`로 P1 시험용 환경을 준비합니다. Windows에서는 `.venv-controls/Scripts/python.exe`, Linux에서는 `.venv-controls/bin/python`을 사용합니다. 현재 P1 시험은 Python 표준 라이브러리를 사용하며 기존 환경의 설치 패키지를 제거할 필요는 없습니다. 필수 시험 환경이 없거나 실행할 수 없으면 검사 실패로 표시하며 자동으로 의존성을 다운로드하거나 통과로 처리하지 않습니다.

등록된 작업은 시작 당시 `gates.json`을 고정하므로 작업 중 검사 설정을 변경할 수 없습니다. 같은 선정 범위의 새 작업도 기존 설정을 고정하므로, 새 작업을 만드는 것만으로 설정 변경이 가능해지지는 않습니다. 향후 설정 변경에는 별도 마이그레이션 절차가 필요하며 이 버전은 그 절차를 제공하지 않습니다. 현재 작업의 등록을 삭제하거나 검사를 끄는 방법으로 우회하지 않습니다.

## 변경 영향에 따른 시험 선택

이 기능이 게시된 **이후 시작한 작업**만 기준 커밋의 `.agent-work/impact-tests.json`을 등록에 고정합니다. 기존 작업의 등록·스냅샷·필수 전체 P1 시험은 바뀌지 않습니다. `gates.json` 자체의 변경 금지는 유지합니다.

`python runtime/control_gate.py select-tests --task <작업ID>`로 실제 필수 suite와 경로별 선택 이유·digest를 확인합니다. 기존 문서·모듈 지침·스킬·지식·eval·생성 어댑터는 `impact-document-integrity`(sync_codex 확인, doctor, 결과 계약, UTF-8/충돌 표식 검사)를 선택합니다. 개별 runtime 모듈은 대응표의 명시된 테스트를 선택하며 섞인 범위는 합집합입니다. 새 파일·삭제·모드 변경·미등록 경로·소유권 밖 dependency 변경은 전체 P1입니다. 대응표, gates, 결과 스키마, AGENTS, workflows 및 공용/선택 runtime 경로는 대응표보다 우선하여 항상 전체 P1입니다.

evaluator는 기존 평가 필드에 `impact_digest`와 모든 소유 경로의 검토 근거 문자열을 담은 `impact_review` 객체를 추가합니다. 선택 결과는 시험 증거에 저장되고 평가·제출 시 다시 대조합니다. 영향 범위가 모호하면 `python runtime/control_gate.py promote-full --task <작업ID> --reason "구체적인 전체 시험 사유"`로 되돌릴 수 없는 전체 승격을 합니다. 매 릴리스 직전에도 이 명령으로 전체 P1을 수행합니다. 수동 릴리스 점검을 택한 이유는 대응표 누락을 정기적으로 재검증하면서 자동 예약·추정 게시 횟수에 의존하지 않기 위해서입니다.

## 미완료 작업의 후속 처리

동일 저장소와 정확히 같은 네 범위로 새 P1 후속 작업을 등록하고 running으로 전환합니다. 원작업은 다시 열거나 기록·스냅샷을 덮어쓰지 않습니다.

- `repoctl.py transfer-ownership --task <후속ID> --source-task <원ID> --path <정확한파일>`: partial 제출 때 보존된 후보와 현재 파일의 Git 표현·모드·원시 해시가 모두 일치할 때만 소유권을 받습니다. 후보 증거가 없는 과거 작업은 추측으로 이전할 수 없습니다. 이후 수정은 후속 작업의 시험·독립 평가·봉인 대상으로 처리합니다.
- `repoctl.py prepare-records-only --task <후속ID> --source-task <원ID>`: partial·failed 제출 또는 cancelled 작업의 보존된 세 기록과 해당 공유 인덱스 항목을 명시적으로 승인합니다. 비어 있는 소유 목록에서 시작하며 소스 파일 추가는 금지됩니다. 양쪽 `recovery/` 아래에 같은 추가 영수증을 남깁니다. 원기록은 보존하며, 명세와 해시가 어긋난 기록은 거절합니다.

두 절차 모두 후속 작업의 정상 시험·evaluator·submit·finish를 거쳐 게시합니다. 기존 원격·브랜치·실제 커밋 검사와 다른 인덱스 항목 불변 검사는 유지합니다. 원작업의 로컬 `runs/`와 기준 Git 객체가 필요합니다. 기록만 있는 새 clone에서 원작업 상태를 추측하지 않습니다. 기록 전용 게시에도 실행 dependency의 커밋 일치가 필요하므로 미게시 runtime 변경이 남아 있으면 차단됩니다. 이때 원작업의 `runs/`·Git 기준 객체·보존 기록을 함께 가진 별도 깨끗한 체크아웃에서 수행합니다. 기록을 임의 수정하거나 소스 변경을 기록 게시에 섞지 않습니다.

한 후속 작업은 원작업 하나만 처리합니다. 여러 닫힌 작업의 인덱스가 함께 미게시 상태이면 다른 항목 불변 검사로 차단합니다. 해당 원작업만 포함된 기준 인덱스·로컬 증거를 갖춘 별도 체크아웃에서 하나씩 처리하며, 원기록이나 공유 인덱스를 수동으로 고쳐 우회하지 않습니다. partial 후보의 파일 봉인은 시험 환경이 없어도 가능하며, 제품 파일이 없는 partial은 이전 가능한 후보를 만들지 않습니다.

## 게시 직전 비밀값 검사

일반 작업과 닫힌 작업 기록 전용 게시 모두 커밋 직전의 Git 스테이징 내용과 푸시 직전의 실제 커밋을 검사합니다. 재시도에서도 같은 커밋을 다시 검사합니다. 대상은 게시되는 변경 파일의 전체 내용이며 생성된 작업 기록도 포함합니다. 무관한 작업 파일과 과거 전체 이력은 검사하지 않습니다.

현재는 외부 실행 파일 없이 동작하는 최소 정규식 검사로 개인키 시작 블록, AWS·Google 키 형식, Azure 연결 키, 비밀번호·토큰 할당과 시험용 canary를 차단합니다. 따옴표 안의 비어 있지 않은 값은 앞 공백·공백만 있는 값도 차단하며, 빈 할당과 따옴표 없는 꺾쇠 자리표시는 통과합니다. 탐지하면 푸시하지 않고 파일 경로와 줄 번호만 표시합니다. 검사 자체가 불가능하면 차단하며 위치를 특정할 수 없는 파일 오류는 줄 번호 0입니다. 비밀값이나 일치한 본문은 보고서에 남기지 않습니다.

오탐 예외는 `.agent-work/secret-scan-allowlist.json`의 `paths` 배열에 저장소 상대 파일 경로를 정확히 등록하는 방법 하나뿐입니다. 와일드카드·디렉터리·인라인 예외는 지원하지 않습니다. 허용 목록 변경도 작업 소유 파일로 등록하여 검수·게시해야 적용되며, 작업 트리만 고쳐서는 이미 준비된 커밋의 검사를 우회할 수 없습니다. 허용 파일은 전체 내용이 검사 제외되므로 최소한으로 사용합니다.

검사 실패 시 커밋 전에는 파일이 스테이징된 상태로 남습니다. 값을 제거하고 해당 파일만 스테이징 해제한 뒤 기존 검증·검수를 갱신하여 `finish`를 다시 실행합니다. 이미 생성된 커밋에서 발견하면 커밋을 보존하고 푸시를 차단하므로 작업 트리 수정만으로 재시도하지 말고 정상 복구 절차로 처리합니다.

이 검사는 포괄적인 비밀 탐지기가 아닙니다. 사용자 정의 형식·압축 내부·암호화 데이터는 보장하지 않습니다. UTF-8 및 BOM이 있는 UTF-16/32를 처리하며, 모호한 NUL 포함 데이터·손상된 Unicode·16 MiB 초과 파일은 검사 불가로 차단합니다. 단일 파일 허용 목록으로 명시적으로 검토한 예외만 처리할 수 있습니다.

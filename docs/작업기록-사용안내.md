# 저장소별 작업 기록 사용 안내

## 기본 동작

에이전트 정의는 multi에서 관리하고, 실제 작업 기록은 작업 대상 Git 저장소의 .agent-work/에 저장합니다. 새 채팅은 AGENTS.md의 시작 절차에 따라 기록과 현재 Git 상태를 읽습니다. 대화의 기억만으로 작업을 이어가지 않습니다.

- 에이전트용 규칙과 작업 명세(spec.md)는 영어입니다.
- 사용자 보고서(report.ko.md, outputs의 결과 보고서)는 한국어입니다.
- 작업 시작: 저장소 선택 → 기존 기록 읽기 → 새 작업 또는 후속 작업 생성.
- 작업 중: 결정, 변경 파일, 검증, 미해결 사항을 result.json에 갱신하고 checkpoint 실행.
- 종료: validate와 submit 실행. 연결된 저장소에 명세가 자동 갱신됩니다.
- 현재 multi는 자동 게시가 활성화돼 있습니다. 작업 완료 후 에이전트가 이번 작업 파일과 명세를 커밋하고 origin/main에 푸시합니다.

## 처음 받은 컴퓨터 또는 새 체크아웃

Python 3.11 이상과 Git이 필요합니다. multi 루트에서 실행합니다.

```powershell
python runtime/sync_codex.py --write
python runtime/agentctl.py doctor
python runtime/repoctl.py register --id multi --path .
python runtime/repoctl.py resume --repo multi
```

다른 저장소는 해당 저장소를 별도로 clone한 후 등록합니다.

```powershell
python runtime/repoctl.py register --id app --path C:/work/app
python runtime/repoctl.py resume --repo app
```

로컬 경로 목록 runtime/repos.local.json은 컴퓨터별 설정이므로 Git에 올리지 않습니다. 다른 컴퓨터에서는 register를 다시 실행합니다. 저장소 ID와 UUID는 .agent-work/repository.json에 보관합니다.

## 작업 생성·기록·재독

```powershell
python runtime/agentctl.py init --module coding --task example-task --repo multi --project multi --service agent-framework --environment development --issue example-issue --objective "Implement the requested change" --criterion "Relevant checks pass"
python runtime/agentctl.py transition example-task running
# runs/example-task/result.json에 진행 내용과 근거를 갱신합니다.
python runtime/repoctl.py checkpoint --task example-task
python runtime/repoctl.py resume --repo multi --task example-task
python runtime/agentctl.py validate example-task
python runtime/agentctl.py submit example-task
```

새 체크아웃에 과거 runs/가 없으면 저장된 명세를 읽고, 새로운 작업 ID로 후속 작업을 만듭니다. 과거 작업의 실행 상태나 스냅샷을 꾸며 복원하지 않습니다. 증거 경로가 이전 컴퓨터에만 있으면 미확인으로 취급하고 필요한 검증을 다시 실행합니다.

## 새 채팅에서 요청하는 예시

> multi 저장소의 작업 기록을 읽고 이전 작업의 미해결 사항을 알려줘.

> app 저장소의 example-task 명세를 읽고, 현재 브랜치와 파일 상태를 확인한 다음 후속 작업을 시작해줘.

## 적용 범위

multi에서 시작한 채팅은 AGENTS.md의 절차를 따릅니다. 다른 저장소에서 직접 새 채팅을 열 때는 해당 저장소의 AGENTS.md에도 같은 기록 읽기 규칙이 있어야 합니다. 등록만으로 다른 프로젝트의 규칙을 덮어쓰지는 않습니다. 강제 종료 직전의 미저장 내용은 복구할 수 없으므로 작업 중간에 checkpoint를 남깁니다.

## Git 저장소 교체

DurianCream/private의 main 내용을 이 프레임워크로 교체하며 이전 커밋 이력을 보존합니다. 기존 디렉터리는 새 커밋의 파일 트리에서 제거됩니다. 과거 세션 로그, 임시 파일, 컴퓨터별 경로 설정은 게시 대상에서 제외합니다.


## 자동 시작 및 완료 게시

이제 새 multi 채팅에서 기록을 읽으라고 별도로 요청하지 않아도 됩니다. 에이전트는 먼저 startup으로 저장된 기록을 읽고, 현재 요청에 필요한 내용을 확인합니다. 과거의 무관한 미완료 작업을 임의로 실행하지는 않습니다.

완료된 구현 작업은 검증·제출 후 finish를 실행해 작업 명세와 자신이 수정한 파일을 자동 커밋·푸시합니다. 파일 목록은 에이전트가 관리하므로 사용자가 명령이나 경로를 직접 입력할 필요가 없습니다. 인사·설명 등 파일 변경이 없는 대화에는 빈 커밋을 만들지 않습니다. 실패·미완료 작업은 기록을 저장하고 미완료 사항을 보고합니다.

자동 게시 대상은 .agent-work/automation.json에 설정된 DurianCream/private의 origin/main입니다. 다른 저장소 등록만으로 자동 푸시 권한이 생기지는 않습니다. 이번 작업에 한해 커밋이나 푸시를 생략하라고 말하면 해당 지시를 우선합니다.

원격이 앞서 있거나 다른 작업의 변경과 충돌하면 그 이유를 알려줍니다. 기존 변경을 되돌리거나 강제 푸시하지 않습니다. 인증·네트워크 문제로 실패하면 이미 만든 커밋을 보존하고 재시도합니다.

내부 실행 순서는 startup → init --repo (기준 상태 저장) → track (작업 파일 등록) → checkpoint → validate → submit → finish입니다. 이 절차는 AGENTS.md를 읽은 에이전트가 실행하며, 앱이 닫혀 있는 동안 독립적으로 실행되는 백그라운드 서비스는 아닙니다.


## 프로젝트·서비스·환경·이슈 분리

기록의 저장 경로는 기존 .agent-work/tasks/<task-id>/를 유지하고, 각 작업의 네 가지 구분을 binding·record·index·영어 명세에 저장합니다. 한 작업의 구분은 최초 지정 뒤 변경할 수 없습니다.

| 구분 | 예시 |
|---|---|
| 프로젝트 | customer-a, internal-infra |
| 서비스 | softether, firewall, database |
| 환경 | production, development, staging |
| 이슈 | vpn-disconnect-001, bandwidth-limit-002 |

새 채팅에서 에이전트가 요청 내용을 보고 구분을 선택합니다. 사용자가 명령어나 플래그를 입력할 필요는 없습니다. 예를 들어 고객 A의 운영 SoftEther 접속 장애를 요청하면 해당 범위에 일치하는 기록만 읽습니다. 운영인지 개발인지 알 수 없으면 그 구분을 먼저 확인합니다.

아무 범위도 선택하지 않은 startup은 목록용 식별 정보만 반환합니다. 모든 구분이 정확히 일치해야 전체 기록을 읽으며, 다른 프로젝트·서비스·환경·이슈의 기록이나 최신 기록으로 대체하지 않습니다. 병렬 채팅끼리 공유하는 마지막 선택 범위도 저장하지 않습니다.

기존 미분류 기록은 삭제하지 않고 보존합니다. 자동 읽기 대상에서는 제외하며, 요청과 관련된 특정 과거 작업을 명시적으로 조회할 때만 미분류 상태임을 표시해 읽을 수 있습니다. 기존 제출 보고서와 스냅샷은 변경하지 않습니다.

내부 명령 예시:

    python runtime/repoctl.py startup --repo multi --project internal-infra --service softether --environment production --issue vpn-disconnect-001

같은 서비스라도 환경이나 이슈가 바뀌면 새 작업을 생성합니다. 새로운 구분 기능을 적용하기 전에 생성한 진행 중 작업은 set-scope로 최초 구분을 부여할 수 있지만, 이미 지정한 범위를 바꾸거나 제출된 보고서를 다시 분류하지 않습니다.


## 기존 미분류 기록의 근거 기반 분류

과거 기록의 원본 JSON·명세·보고서·스냅샷은 수정하지 않습니다. 분류 결과는 .agent-work/classifications/에 별도 JSON으로 저장하고 원본 파일 해시와 연결합니다. 네 구분이 모두 확인된 confirmed 기록만 정확한 범위 조회에서 자동으로 읽힙니다. needs-review 기록은 목록에 미확인 항목만 표시하고 자동 본문 조회에서는 제외합니다.

이전에 runs/에만 있던 기록은 .agent-work/legacy/에 원본 작업·결과·버전 스냅샷 목록·생성 보고서의 사본을 보존합니다. 원본 기록에 Git 상태가 없으면 알 수 없음으로 유지합니다. 당시의 테스트·완료 표시는 과거 관찰이며 현재 상태를 다시 검증했다는 뜻이 아닙니다.

원본이 변경돼 분류 근거의 해시와 맞지 않으면 자동 읽기를 중단합니다. 새 clone에서도 해시가 유지되도록 해당 기록 파일의 Git 줄바꿈 자동 변환을 끕니다.

이번 검토의 확정·보류 목록은 .agent-work/reports/legacy-classification.ko.md에서 확인할 수 있습니다. SoftEther 연구·런북은 대상 프로젝트와 실제 환경을 확인하기 전까지 자동 본문 조회에서 제외합니다.

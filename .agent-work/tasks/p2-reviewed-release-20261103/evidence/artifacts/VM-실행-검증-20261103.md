# P2 테스트 VM 실행 검증

## 1. 기본 정보

- 작업: `p2-host-isolation`
- 범위: `multi / agent-framework / development / p2-host-credential-isolation`
- 담당: infrastructure/p2_host
- 환경: 사용자 제공 Ubuntu 24.04.2 LTS VM, kernel 6.8.0-147, systemd 255, bubblewrap 0.9.0
- 상태: **실제 VM의 수동 실행·검증·로컬 게시 경로 검증 완료. 전체 P2 완료는 아님.**

## 2. 목표 및 완료 기준

기존 `sandbox_setup_failed` 원인을 수정하고, 실제 격리 실행의 정상 결과와 보호된 게시 경로를 확인한다. 직접 Git 쓰기, 합성 자격증명 접근, 안전성 검사용 영수증의 게시 전용, supervisor 종료 후 잔존 프로세스를 검사한다.

## 3. 결과 요약

- root 검증기가 worker UID 994의 실제 격리 실행을 확인하고 출력 해시가 일치하는 검증 영수증을 발급했다.
- 별도 publisher UID 990이 VM 내부 bare 저장소에 게시했다. 같은 요청을 재시도해도 commit은 `fb8b48e52b419f7ecef296ad6e7cdb481d38ae2f`로 유지됐다. 이 commit은 테스트 대상 저장소의 값이며 프로젝트 Git 게시 commit이 아니다.
- 실제 worker의 Git 사용 제어군은 성공했고 보호된 대상 직접 쓰기와 합성 canary 읽기는 거부됐다.
- 안전성 검사용 영수증은 게시 권한으로 인정되지 않았다. 대상 ref 불변을 별도로 확인했다.
- supervisor 강제 종료 후 worker 4개가 모두 사라졌으며, 외부에서 열어 둔 동일 output inode의 쓰기도 멈췄다.

## 4. 수행 내용

systemd 255에서 명시적 `User=root`와 syscall 필터 조합이 시작 전에 `CAP_SETUID`를 제거하는 것을 실제 비교 시험으로 확인했다. executor unit은 system service의 기본 root를 사용하도록 바꾸고, 기존 root 확인·NNP·namespace·seccomp·자원 제한·정리 절차는 유지했다.

실패한 child의 stderr는 root 전용 파일에 최대 4KiB만 기록하며 nonce를 제거한다. 원인 추적에만 사용한 추가 capability 단계 진단은 제거했다. 전용 bwrap/AppArmor 설정과 재현 절차는 별도 영문 명세에 보존했다.

## 6. 검증 결과

- 재개 후 executor 실제 실행 10회: 원인을 단계적으로 좁힌 실패 6회, 정상 검증 성공 2회, 안전성 probe 성공 1회, 의도한 SIGKILL 시험 1회
- publisher 실제 실행 4회: 게시 성공 2회, 동일 키 재시도 성공 1회, 안전성 영수증 게시 거부 1회
- 후보 없는 UID 원인 분리 probe 4회, host worker 직접 접근 거부 probe 1회
- 로컬 집중 검사 3개 통과. 변경 없는 전체 suite는 재실행하지 않았다.
- 실제 sandbox에서 Git 제어군, 직접 push 차단, canary 차단, 입력 쓰기 차단, 5개 네트워크 socket family의 `EPERM`을 확인했다.
- 종료 시험은 경로가 사라진 것만 확인하지 않았다. 외부 FD를 유지하여 동일 inode 크기가 21→73 bytes로 증가한 뒤 강제 종료 후 73 bytes로 안정됨을 확인했다. worker 및 cgroup 정리는 약 0.31초 내 완료됐고 성공 영수증은 발급되지 않았다.
- 매 실행 후 namespace 제한을 0으로 복원했다. 최종 상태는 두 service 모두 inactive/static, worker 프로세스 0이며 정상 사례의 job을 복원해 두었다. 서비스는 자동 시작되지 않는다.

## 7. 미해결 사항 및 다음 조치

독립 최종 검토와 검토된 버전의 최종 적용·프로젝트 Git 게시는 별도 절차다. 영수증은 600초 만료이므로 새로운 작업은 새 검증이 필요하다.

현재 구현은 동일 Linux 호스트에서 운영자가 시작하는 실행·검증과 local-bare 게시를 다룬다. worker 업로드, broker에서 privileged executor로 연결하는 RPC, 호스트 간 인증, 외부 HTTPS/GitHub 게시, 실제 자격증명 회전, 현재 데스크톱 에이전트의 모든 도구·connector 격리는 미구현 또는 미검증이다. 합성 canary만 사용했으며 실제 키·토큰을 읽지 않았다.

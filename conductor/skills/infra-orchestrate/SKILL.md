# 다섯 단계 조율 프로토타입

주 대화가 조율을 맡는다. 필요한 역할과 기록을 사용하고 기존 사용자 승인 범위·인프라 지침·플랫폼 권한을 유지한다.

1. 사용자의 목표와 대상, 실제 실행 여부, 최소 한 완료 기준을 정한다. 관련 없는 요구사항이나 검사를 추가하지 않는다.
2. `infra_planner`에게 필요한 근거 조사와 의존 관계가 있는 작업 계획을 받는다.
3. 선행 조건이 충족된 작업을 `infra_worker`에게 배정한다. 독립 작업만 병렬로 나누고 공유 파일·서비스 변경 범위를 조정한다.
4. 완료된 버전을 `infra_critic`에게 전달한다. 지적이 있으면 작업 담당이 수정하고 영향을 받은 비평을 다시 수행한다.
5. 최종 버전과 증거를 `infra_acceptance`에게 전달한다. 프로그램 검사와 실제 내용 검토를 함께 확인한 뒤 한국어 보고서를 전달한다.

하위 역할에게 목표·범위·허용 행위·앞선 결과·완료 기준·반환 형식을 준다. 역할의 결과를 받아 주 대화가 전달 기록을 저장한다. 읽기 전용 역할에게 파일 저장을 맡기지 않는다.

[단계 전달 프로토콜](/home/dhyun/ai-agent-repos/acceptance-gate/skills/infra-evidence-gate/references/protocol.md)을 사용한다. 실행 폴더는 허용된 로컬 위치를 선택한다. 작업 대상이 Git 레포라면 기록 폴더가 코드 커밋에 섞이지 않도록 한다. 회사 정보나 로그는 필요한 부분만 민감정보를 제거해 저장한다.

기록된 명령을 검사기가 자동 실행하지 않는다. 필요한 실제 검사는 작업 단계에서 승인 범위에 따라 수행하고 증거를 남긴다. 최종 프로그램의 통과만으로 기술적 정확성이나 운영 성공을 주장하지 않는다.

서브 에이전트가 없거나 역할 선택이 지원되지 않으면 그 기능은 확인 불가로 명시하고 지원되는 작업을 주 대화에서 완성한다. 짧은 확인 질문에 다섯 개 세션을 생성하지 않는다.

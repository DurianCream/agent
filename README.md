# multi: 모듈형 에이전트

**P2 호스트 격리 작업은 동결 상태입니다.** 별도 OS 계정·WSL·Codex 샌드박스와 승인 등 호스트 대안의 불충분성 평가, 행동 평가에서 확인한 게이트 우회 증거를 재개 검토 조건으로 기록합니다. 검토 후 명시적인 재개 결정이 필요합니다.

코딩·인프라·오픈소스 R&D와 공통 관리 역할을 제공하는 프로젝트입니다. 전문 역할이 작업하고 별도 evaluator가 검증합니다.

에이전트 지침은 영어, 사용자 보고서는 한국어로 작성합니다. 작업 대상 저장소별로 .agent-work/에 작업 명세를 남겨 새 채팅에서 다시 읽을 수 있습니다.

- [설치 및 작업 기록 사용 안내](docs/작업기록-사용안내.md)
- [P0 계약 검증과 관찰 모드 사용 안내](docs/P0-실행통제-사용안내.md)
- [P1 제출·게시 검사 사용 안내](docs/P1-제출-게시-검사-사용안내.md)
- [디렉터리 구조와 에이전트 역할](docs/디렉터리-구조와-역할.md)
- 에이전트 시작 규칙: AGENTS.md
- 역할 목록: registry.json
- 작업 기록: [.agent-work/INDEX.md](.agent-work/INDEX.md)

Python 3.11 이상과 Git이 필요합니다. 처음 clone한 뒤 python runtime/sync_codex.py --write와 python runtime/agentctl.py doctor를 실행하세요. 모델·호스트 기능과 훅 지원은 실행 환경에 따라 달라집니다.

새 채팅은 저장된 작업 기록을 먼저 읽습니다. 완료된 작업은 명세·한국어 보고서를 저장한 뒤, 이번 작업의 파일만 자동 커밋하고 승인된 origin/main에 푸시합니다. 별도로 기록 읽기나 푸시를 요청할 필요가 없습니다. 충돌이나 인증 문제는 원인을 보고하며 강제 푸시하지 않습니다.

작업 기록은 프로젝트·서비스·환경·이슈의 네 가지 구분으로 분리합니다. 새 채팅은 목록 정보로 현재 범위를 확인하고, 네 가지가 모두 일치하는 기록만 자동으로 읽습니다. 범위가 불명확하면 최신 기록을 대신 읽지 않고 필요한 구분을 확인합니다.

현재 체크아웃에서는 `.agent-work/observation.json`이 선정한 개발 작업의 체크포인트·소유 파일 등록과 실제 커밋의 게시 직전에 P0 관찰을 호출합니다. `.venv-controls` 환경이 필요하며, 관찰 결과와 거버넌스·검증 평가는 실행 승인과 구분합니다. 새 clone에서는 위 P0 사용 안내에 따라 고정 환경을 준비하세요.

`.agent-work/gates.json`이 선정한 새 작업은 P1 검사에 등록됩니다. 완료 제출에는 동일한 파일 내용에 대한 필수 시험 실행 기록과 독립 검토가 필요하며, 게시 직전에는 실제 커밋을 다시 대조합니다. 직접 Git 명령이나 구버전 도구의 우회를 막는 호스트·원격 서버 보호는 별도 단계입니다.
